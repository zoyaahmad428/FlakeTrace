What this evidence is and is not

Every link comes from reading the source: an assignment, a call that reaches the field, a missing teardown. That is enough to name a cause and build a patch.

It is not execution. Confirming the failure means running the two tests in order, which the replay below does when a JDK is present.

Reading the edges.
      direct — the test names the field itself, at the line shown.
      via a call — the test reaches the field through a call into production code; the analysis followed the call chain to get there, so the attribution is to the chain, not to a line that mentions the field.
      restored — the writing class resets the field in teardown, so that write cannot leak into a later test.

      
Reflective and native access appears nowhere on this graph. Source-level analysis cannot see it, and its absence here is not evidence that it does not happen.

Why not fix the field itself
          
Making the field non-static is the durable fix, but it changes production code and every caller. FlakeTrace limits patches to test sources and flags the deeper change for a human.
