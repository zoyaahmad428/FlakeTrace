# W35 Pair Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `--search pairs` diagnoses a known victim from `[candidate, victim]` pairs when no order makes it fail.

**Architecture:** A `pair` exploration phase in the budget ledger; `find_pair` beside `find_polluter`; `run_steps`
branches on `search_mode` and both modes share one certification tail (`_certify`); the CLI adds the flag, the
leakage refusal, a `pairs:` line and order mode's `next:` line.

**Tech Stack:** Python 3.11 `unittest`, the scripted `FakeOrderRunner`, `FakeRanker`; real runs need JDK 8 + Maven.

**Spec:** `docs/superpowers/specs/2026-11-22-w35-pair-mode-design.md`, ADR-016 (revised), Interface 9.

## Global Constraints

- Order mode's behaviour and verdicts do not change (real F1–F4, N1–N4).
- `DiagnosisRuns` new fields: `search_mode: str = "order"`, `reproduced_by: Optional[str] = None`,
  `pairs_tried: int = 0`, `scope_size: int = 0`. Record header key `search_mode`.
- `pair` is exploration (`EXPLORE`), never the reserve; `BudgetAccount.spent["pair"]` always present.
- A failing pair is adopted only when its one re-run fails with a matching signature (`FailureSignature.matches`).
- `--order` with `--search pairs` → exit 2; `run_steps(order_given=True, search_mode="pairs")` and a priority list
  with pairs → `DiagnoseInputError`.
- The `pairs` limitation sentence is M3's (report side); the runner only supplies the fields.

## Review Focus

1. Zero candidates in scope (package with only the victim) → `NOT_REPRODUCED` with the alone tally, no crash. (Task 2)
2. A pair that crashes (synthetic failure) is never re-run or adopted; the scan continues. (Task 1)
3. The re-run fails with a *different* real signature → not adopted. (Task 1)
4. A polluter that sorts **after** the victim in discovered order is still a candidate. (Task 2)
5. Budget cut between a failing pair and its re-run → `BUDGET_EXHAUSTED`, nothing blamed. (Task 2)
